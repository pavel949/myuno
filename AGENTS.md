## Core execution invariants

- Preview, published, myuno.app and drafts share production data/settings, not staging; migrations and edge deploys are live. Use forward/additive or restrictive changes with security-preserving rollback in `docs/hardening/rollback/`.
- One Operational Reality: never create parallel Property, Booking, Availability, Pricing, CRM, Identity, Finance/Ledger, Service Commerce or PMS truth.
- `orders` owns canonical commercial-order state where used; `property_bookings` owns rental inventory; verified payment writers/`payment_intents` own payment-provider state where applicable; `ledger_entries` owns accounting.
- Preserve `service_orders` as the active service request/booking workflow. Creating `service_orders` does not imply `orders`. Any service→commercial-order bridge is explicit, idempotent, reconciled and deterministically linked; avoid multiple active commercial orders for one service transaction unless an explicit retry/version contract requires it.
- `providers.id` differs from `orgs.id`; commercial counterparty resolution uses trusted provider→org mapping. Missing mapping may block settlement but need not block legitimate request-only service flows.
- Service commerce modes are REQUEST / BOOK / BOOK+PAY. Never force all services into one checkout model. Each vertical defines capacity/hold independently of payment; payment never substitutes for capacity reservation.
- Structured service requests use Marketplace first; Concierge is human escalation. Concierge may keep an orchestration case, but it must not become booking/payment/inventory/service-order authority.
- Booking inventory uses half-open `[check_in, check_out)`; DB constraints/holds remain final authority.
- Generic `uno_team` is employment, not global private authority. Operating Space = WHERE; RBAC/module/action = WHAT. Space scoping constrains employee/management access and does not replace independently verified customer/owner/provider/public rights.
- Empty/invalid authorized scope never means All. Scope preferences and cache never authorize data.
- Public property/provider/service/salon reads use safe allowlisted projections; private operational records require object/server authorization.
- Money-moving functions derive actor server-side and never trust client identity, totals, payment status or recipient fields.
- Before creating a new table, enum, hook, context/provider or workflow engine, search current code/schema for the canonical implementation and prove it cannot represent the requirement.
- Unknown is UNKNOWN, not false/default. Never invent catalogues, prices, availability, provider mappings, property facts or production state.
- High-risk sequence: Audit → Design → Isolated Tests → Implement → Verify → GO/NO-GO. Do not automatically continue after money, inventory, RLS, schema or enforcement changes.
- UI tests use synthetic/stubbed data and must not mutate production business records.
- Calendar/date logic uses shared civil-date helpers; avoid UTC/date-only parsing that shifts Phuket/Bangkok dates.
- Convergence/audit docs are evidence, not permanent normative authority. Promote accepted durable rules into PROJECT.md / AGENTS.md / canonical docs.

- Accepted quote snapshots may preserve historical agreed commercial state without becoming competing canonical truth.
- Service requests are not GMV; recognize Marketplace GMV/revenue only from the configured verified commercial/financial event for the vertical.
- Forecast/pending/provisional finance is labelled non-posted and excluded from realized P&L until supported by canonical accounting truth.
- Current P0 is a moving pointer: after an accepted gate, advance to the next unresolved gate and do not rerun accepted work without new contrary evidence.

## Source-backed security contracts

Preserve these concrete guards when applying the constitution. The source references below are implementation evidence, not proof of deployed privileges, enabled enforcement or completed operational acceptance. Verify current source and dated read-only evidence before changing a guard; apply PROJECT.md §20. A roadmap is not permission to replay migrations, seed assignments, enable enforcement or perform a live transaction.

- Wallet debit/top-up primitives remain service-role-only; never expose arbitrary user IDs or amounts as a customer payment/refund API. Preserve finite positive amount validation. Actor and amount checks alone do not certify server-authoritative pricing. Source: [wallet containment](drizzle/migrations/0033_restrict_unchecked_wallet_mutations.sql).
- Transfer refund containment fails before Stripe or business mutation when no governed atomic reversal writer is available. Failed, missing or ambiguous payment lookup, order status and metadata never prove a refund. Do not restore manual-success markers. Source: [refund-transfer-order](supabase/functions/refund-transfer-order/index.ts).
- Inventory predicates in browser and edge code mirror `property_booking_holds_inventory` / `property_bookings_no_overlap`; order refund/expiry and booking lifecycle statuses remain separate domains. Source: [browser predicate](src/lib/propertyInventory.ts), [edge predicate](supabase/functions/_shared/property-inventory.ts), [SQL predicate](drizzle/migrations/0019_canonical_inventory_status_predicate.sql) and [lifecycle mapping](drizzle/migrations/0020_preserve_property_booking_lifecycle_status.sql).
- Commercial service booking resolves `orgs.id` only from explicit trusted `provider_org_links`; missing/ambiguous mapping blocks that commercial path, never substitutes a provider ID. Preserve independently valid request-only `service_orders` and its server price/provider/busy-slot validation. Source: [catalogue loader](src/hooks/useServiceBookingCatalogue.ts), [commercial model](src/lib/services/serviceBookingModel.ts) and [service-order trigger](supabase/migrations/20260924114852_9a588fff-8d77-4585-99b8-21390f3cce73.sql).
- Operational-scope consumers require the actor-bound resolver, a ready-state property allowlist and actor/company/scope/revision-bound cache keys. Stored preferences, legacy/error states and empty arrays do not authorize data. The shadow controller's existence does not prove runtime adoption or live enforcement. Source: [resolver RPC](drizzle/migrations/0022_operating_scope_resolver.sql), [RPC reader](src/lib/readOperationalScope.ts) and [controller/cache contract](src/lib/operationalScope.ts).
- Private operational policies retain private-only helpers; generic employment cannot become private authority. User-invoked privileged handlers authorize actor/object/company/action before creating a service-role client. Source: [private helpers](drizzle/migrations/0028_uno_team_private_helpers.sql), [private policies](drizzle/migrations/0029_uno_team_private_policies.sql) and [authorization ordering](supabase/functions/_shared/operating-space-auth.ts).
- Enforced-company managed-property creation and Space reassignment use checked actor-bound RPCs; preserve private base-table boundaries and the public allowlisted property projection. Source: [checked onboarding/reassignment](drizzle/migrations/0024_operating_cutover_blockers.sql), [private property reads](drizzle/migrations/0027_close_authenticated_private_property_reads.sql) and [onboarding capability](drizzle/migrations/0031_checked_onboarding_private_capability.sql).
- Public provider/service/salon and resort-room reads use read-only allowlisted catalogue projections. Resort availability is a checked aggregate; room assignment or a quote is not a reservation. Reuse shared civil-date/`hotelQuote` rules. Source: [public service catalogues](drizzle/migrations/0032_catalog_notification_private_boundaries.sql), [public room catalogues/availability](drizzle/migrations/0034_public_resort_catalog_projection.sql) and [hotelQuote](src/lib/hotelQuote.ts).
- Property-submission alerts accept only an object ID, authorize the persisted pending owner/admin relation and resolve current protected admin recipients. Interactive booking-message dispatch requires a readable confirmed property order and stored property/company booking-edit authority (or verified platform admin); scheduler-secret access remains separate. Internal property reports remain owner-recipient-bound. Source: [submission handler](supabase/functions/notify-admin-property-submission/index.ts), [booking-message access](supabase/functions/execute-booking-message-rules/access.ts) and [report handler](supabase/functions/send-property-report/index.ts).
