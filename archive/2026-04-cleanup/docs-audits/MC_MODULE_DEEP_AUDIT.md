## PART 2: CORE OPERATIONS TEST

1. **PROPERTY ONBOARDING (Add property → link to owner contact → set rates → publish listing)**  
   **Working?** Partially.  
   Add Property flow exists at `/mc/properties/new` (AddProperty + PropertyWizard): basic info, location, photos, pricing; wizard can create/link owner contact (crm_contacts with company_id from active org). Properties table has `management_company_id`, `owner_id`, `owner_contact_id` — wizard uses activeCompany/activeOrg for company_id when creating owner contact. Submitting the wizard creates/updates the property. Rates are managed on a separate page (RateManagementPage); listing “publish” is effectively approval_status/visibility handled elsewhere. **Missing:** Explicit “link to owner contact” step in wizard (owner contact can be created); single flow “set rates then publish” is split across screens; no explicit “publish listing” button on one screen.

2. **TENANT MANAGEMENT (Place a tenant → store contact info → link to property → set lease dates)**  
   **Working?** No.  
   There is no dedicated “tenant” entity or “place tenant” flow. Contacts can have `contact_type = 'tenant'`, and CRM has contacts; but there is no “tenant placement” form (link tenant contact to property + lease dates). Lease agreement document template exists (Documents page) with variables for tenant_name, dates, etc., but no tenant–property–lease record in the traced code. **Missing:** Tenant table or tenant–property assignment with lease dates; UI to place a tenant and set lease.

3. **TASK & MAINTENANCE (Create maintenance task → assign to staff → track to completion → notify owner)**  
   **Working?** Partially.  
   Create task: Operations page and Calendar have CreateServiceTaskDialog; task type includes `maintenance`; tasks go to `property_operational_tasks` (property_id, task_type, scheduled_date, status, assigned_to). So create and track (complete, status) work. useOperationalTasks does not filter by assigned_to for “my tasks”; assignment is stored. **Missing:** Assign to staff is present in task model (assigned_to); UI to assign from task card/detail may exist in OperationalTaskCard or elsewhere — not fully traced. “Notify owner” on completion is not present in the traced code (no notification trigger or UI for it).

4. **FINANCIAL TRACKING (Record rent received → record expense → see P&L per property → generate owner report)**  
   **Working?** Partially.  
   Record income/expense: property_financials is used with transaction_type income/expense, category (rent, maintenance, etc.); usePropertyFinancialsFull uses getAccessiblePropertyIds(activeCompanyId) so MC sees all company properties’ financials. Create transaction is in usePropertyFinancials (createFinancial). Finance overview shows aggregates; financials list/detail (OwnerFinancials, etc.) show per-property. **Missing:** “Generate owner report” (e.g. monthly PDF/statement for owner) is not implemented in the traced code. financial_categories exists and is used in settings (FinanceCategorySettings, useFinancialCategories); /mc/finance uses INCOME_CATEGORIES/EXPENSE_CATEGORIES from usePropertyFinancials (in-code), not necessarily financial_categories table for display.

5. **OWNER REPORTING (Owner logs in → sees their property → sees financials → sees upcoming bookings)**  
   **Working?** Partially.  
   Owner portal: `/my-property` (OwnerPortalDashboard) uses useMyPortalSettings — returns properties where owner has portal access (owner_user_id = user). OwnerPortalPropertyView at `/my-property/:propertyId` shows one property. Portal settings (owner_portal_settings) control what owner sees (show_financial_statements, show_booking_calendar, etc.). So owner can see their properties and, if enabled, financials and bookings. **Missing:** useMyPortalSettings and OwnerPortalPropertyView implementation details (e.g. whether financials and bookings are actually rendered on property view) not fully traced; if they are wired, flow works; if not, “sees financials / upcoming bookings” may be incomplete.

6. **BOOKING MANAGEMENT (View all bookings across properties → see calendar → manage check-in/check-out)**  
   **Working?** Yes for view and calendar; partial for check-in/check-out.  
   usePropertyBookings and useMultiPropertyBookings use getAccessiblePropertyIds (including companyId), so MC sees bookings for all company properties. Calendar (OwnerCalendar) shows bookings and tasks; day sheet and booking detail exist. Check-in/check-out: operational task types exist (check_in, check_out); booking_operations table exists. useBookingOperations uses booking_operations and property_operational_tasks. Whether MC has a dedicated “check-in/check-out” execution flow (e.g. mark completed, record meter readings) depends on OperationalTaskCard and other detail screens — tasks can be completed. **Missing:** Dedicated check-in/check-out workflow (e.g. form for meter readings, handover) may be in booking_operations or a separate flow; not fully traced. So: view + calendar + task completion = working; full check-in/out workflow = unclear.

## PART 4: VERDICT

**1. Can Ignatev Estate run its daily operations through the MC module TODAY?**  
**Partially.** Core flows work: dashboard, property list and add, calendar and bookings, operations tasks (create/complete), finance overview and financials per property, staff, contacts, CRM, owners, service request and inspection. **Vendors, inventory, and reviews are now company- or property-scoped in code** (useOwnerVendors with company_id when in MC; Inventory and Reviews by allPropertyIds). **Vendors require the migration** (add company_id + RLS) to be applied on the database; once applied, all three are MC-wide. Still missing: tenant/lease management and generated owner report. So daily use is viable for multi-user MC **after applying the MC scoping migration**; tenant placement and owner report remain gaps.

**2. TOP 3 broken or missing pieces that block real operational use**  
- **Vendors migration not applied:** Code is ready (company_id filter and insert), but if migration `20260304120000_mc_scoping_vendors_inventory_reviews.sql` has not been run, owner_service_vendors has no company_id and RLS still restricts to owner_id — staff will not see company vendors until migration is applied.  
- **No tenant/lease management:** No “place tenant” flow, no tenant–property–lease entity, no UI to store lease dates and link tenant to property.  
- **No generated owner report:** No monthly or on-demand owner statement (PDF/view) aggregating financials and bookings.

**3. Fastest fix for operational viability**  
- **Apply existing migration:** Run `20260304120000_mc_scoping_vendors_inventory_reviews.sql` on the Supabase project so vendors are company-scoped (company_id + RLS). Inventory and reviews already work in app with property-scoped queries; migration adds RLS for MC members on those tables. **Estimate:** &lt; 1 hour (run migration + smoke test).  
- **Tenant/lease:** Add minimal tenant–property–lease model and “Place tenant” form. **Estimate:** 2–3 days.  
- **Owner report:** Add “Generate owner report” action with PDF or printable view. **Estimate:** 1–2 days.

**Fastest path:** Apply the MC scoping migration so vendors (and RLS for inventory/reviews) are live. Then prioritize tenant/lease or owner report as needed.
