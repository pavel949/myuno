Feasible

Yes — the foundations already exist. This is a consolidation, not a rebuild.

08

Risks & guardrails

What breaks if you skip a step.
Risk 01

RLS during role-stack migration

Policies today read single active role. Switching to a stack needs every policy reviewed. Mitigate: ship behind a feature flag, run parallel policies, compare for 1 week.

Risk 02

Legacy URL fallout

40+ routes rename. SEO + PWA install shortcuts + deep links in messaging break if redirects miss. Mitigate: generate redirects programmatically from the route registry, audit with existing LEGACY_REDIRECTS tooling.

Risk 03

Company entity RBAC complexity

Introducing companies + company_members with roles-per-company adds a second dimension to permissions. Mitigate: keep it behind a feature flag; migrate one vendor type at a time (providers first, then MCs, then agents, then developers).

Risk 04

Agent drift & hallucination

More agents = more surface for wrong intents. Mitigate: central registry, every intent logged to /admin/agents, kill-switch flag, user always sees "accept / decline" — never auto-executes money moves.

Risk 05

Design-token split (json vs css)

Two sources of truth is already causing friction. Keep tokens.css, delete tokens.json with a lint rule. Don't try to merge — the DS2.0 Navy spec never shipped; cutting it is fine.

Risk 06

Feature freeze fatigue

13 sprints feels long. Mitigate: every phase ships value end-to-end. Phases 1–2 alone deliver the new home — visible, marketable. Don't let the restructure become an invisible tax.
