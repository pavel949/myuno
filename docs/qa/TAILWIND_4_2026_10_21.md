# Tailwind 4 compatibility migration (PR 11)

Base: `fb4b944a4c736f680ddb8e4b178f833030e021b1`. This preserves the dependency PR's ancestry with an additive merge, without importing its stale dependency lock or changing main.

## Implementation

- Tailwind 4.2.2 uses its supported `@tailwindcss/postcss` plugin and CSS import. The existing TypeScript configuration is loaded explicitly with `@config`; all canonical design tokens, security overrides and unrelated dependencies remain intact.
- `tailwind-merge` 3.5.0 understands the v4 utility model. Regression tests cover spacing, colors, dimensions, responsive states, shadows and outline class conflicts.
- The existing custom container, shadow and radius configuration is retained. The compiled output was inspected: container centering/padding/breakpoint and canonical shadow aliases still exist. Existing blur and drop-shadow scales and the three-pixel default ring are preserved explicitly. Default interactive pointer cursors are retained after v4's preflight change.
- Exactly 187 `outline-none` tokens across 186 changed lines in 116 application files become `outline-hidden`, the documented equivalent that preserves the visible outline in forced-colors mode. Each changed file was verified against main as exactly this string replacement. There are no authentication, lifetime-guard, navigation or business-logic changes hidden in that migration.
- A new independent shared-control fixture imports the real Button and Input and actual compiled application CSS. It denies all external requests and data modules; it is registered as a separate, isolated connected-CI browser group. Existing fixture assertions and resource limits remain unchanged.

Official migration guidance: <https://tailwindcss.com/docs/upgrade-guide>. Tailwind v4 requires modern browsers (Safari 16.4+, Chrome 111+, Firefox 128+); no older-browser support is claimed by this change.
