Scope: `pavel949/myuno`, working branch `fix/public-journey-clarity-20261116`, baseline main `65bc193083a1385bd2ec1bdcfba0283aceb35d0d`. These follow-up changes are source candidates, not a publication or business-transaction acceptance claim.

## Findings and corrections

1. **Purchase market selection.** The actual homepage Buy link opens `/property/search?mode=buy`, bypassing `/discover/buy`. The latter previously offered generic sale, newbuild and advisor cards without a direct resale entry. The buyer goal now begins with distinct existing resale/newbuild routes, followed by the full sale catalogue and advice. The actual buy search route also exposes these same two canonical market destinations. Rental search does not receive purchase controls.
2. **Hidden property context.** On a narrow resale page, the beginning of the long tab strip showed unrelated rental choices while the selected resale section was offscreen. The active tab now has an explicit pressed state and is revealed by horizontal scrolling only. Restored vertical page position is not changed. UUID resale detail pages omit that strip.
3. **Resale filters and history.** Area/type/tab lived only in component state; a shared URL or return to the page lost the selection. They are now URL-owned, along with existing canonical sale-price budget bands. Unrelated query/hash/state is preserved; reset only clears owned filter keys. The filter drawer scrolls within the viewport, including a 375×640 screen.
4. **Budget and recorded currency.** Existing sale bands are reused. Their THB budget filters exclude non-THB records, rather than silently comparing different currencies. Card/detail price display uses guarded recorded currency; USD is not passed through the THB conversion callback, and missing/invalid price or currency is shown as on request. JSON-LD omits unknown amount/currency instead of inventing a city/default currency. No amount, tariff or conversion rate is written or inferred.
5. **Actual card and return.** Resale cards were mouse-only containers; the detail Back button always returned to an unfiltered list. They are now native named links with the existing validated `publicJourneyState`. Actual detail Back uses `publicJourneyReturn`, including failed/missing reads. The featured resale row no longer intercepts that canonical link with a state-less callback.
6. **Read/image failure.** Resale list/detail failures no longer masquerade as a confirmed empty/not-found result; retry remains available. Failed photographs have an explicit labelled placeholder rather than a blank/broken image. Card/list facts and prices remain available.
