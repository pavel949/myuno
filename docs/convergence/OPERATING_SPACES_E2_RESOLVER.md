## Canonical API

`src/lib/operationalScope.ts`: `ResolvedOperationalScope`, validation schema,
`OperationalScopeResolver`, `operationalScopeQueryKey`, `scopeAllowsProperty`.
`src/lib/readOperationalScope.ts`: existing client RPC adapter with AbortSignal.
Compose controller with `{read: readOperationalScope, cache: queryClient, storage}`;
**runtime consumers: NONE**. No mounted provider/hook/shell or UI.

Fields: `activeCompanyId`, `status`, `reason`, `enforcement`, `mode` (`space` or
`all_authorized`), `requestedSpaceId`, `activeSpaceId`, `authorizedSpaceIds`,
`authorizedPropertyIds`, `unassignedPropertyIds`, `isCompanyOverseer`, `revision`.
Controller methods: `setContext({userId,activeCompanyId})`, `selectSpace(id|null)`,
`refresh()`, `snapshot`, `dispose()`.

| Situation | Result |
|---|---|
| No company | `not_applicable/no_active_company`; no RPC, personal context untouched |
| No actor / no active membership and no verified oversight | `no_access`, empty IDs |
| Authorized non-enforced company | `legacy/company_not_enforced`, empty IDs; explicit compatibility context, **not** an All allowlist |
| Enforced overseer without selection | All active spaces **in that company** plus explicit truly unassigned properties |
| Enforced overseer with authorized selection | Only assigned properties of selected space, no unassigned |
| Ordinary member one active space | Defaults to that space |
| Ordinary member multiple active spaces | Union of only joined spaces; valid selection narrows property IDs |
| Ordinary member zero spaces | `no_access/space_membership_required`; never company fallback |
| Requested foreign/unauthorized/inactive/deleted ID | `no_access/requested_space_unavailable`; empty IDs; preference cleared, no automatic broadening of that response |
| Failed/malformed/context-mismatched response | Controller `error/scope_resolution_failed`; empty IDs |

`authorizedSpaceIds` lists selectable authorized spaces; `authorizedPropertyIds`
is the narrowed current projection. Properties come only from same-company
`operating_space_properties` plus overseer-only unassigned bucket, never projects.
Properties assigned to inactive spaces are **not** unassigned and are omitted.
No property `is_active`/status invention; downstream domain predicates stay unchanged.
Non-ready states never permit property queries; `[]` always means none.
Legacy intentionally returns no new authorization: existing PMS is unmodified,
and future consumers must handle compatibility explicitly, never omit an ID filter.

Space access is a scope ceiling, **not a module/action permission** or replacement
for staff duty restrictions. E3 must intersect current verified view/edit/export
and property-specific rights; old permissive policies still allow broad company
access outside this reader. No claim of operational team isolation yet.

## Preference and cache lifecycle

Preference key includes user + company; storage is optional and untrusted.
Initial preference is read then revalidated by server. It is saved only after
ready validation, cleared on denial/error, company/account switch and disposal/logout.
Company switches do not reuse the previous selection or the new company's old preference.
Call `setContext` on actor/company changes, `refresh` on revocation or reassignment
events, `dispose` on unmount/logout; none are mounted in E2.

Every refresh immediately closes the previous snapshot, aborts old read,
cancels and evicts **only** `operational-scope-v1` query-prefix data before reading.
Generation guards prevent late old-company/selection responses becoming current.
Existing PMS/profile cache is untouched. Future owned queries must use the
prefix and consume AbortSignal; arbitrary untagged caches are outside this controller.

Server revision is a deterministic MD5 discriminator of actor + canonical JSON
including company, state, enforcement, authorized sets, selection and overseer.
Sorted ID arrays make it stable on equivalent resolution; revoked/changed sets
change it. It is **not a security token**, monotonic counter, module permission
revision or push subscription. Cache key additionally includes actor/company/state/
mode/selected ID/revision. Revalidation is required; cache is never authorization.
