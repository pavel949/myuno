## TL;DR

> **Bilingual UI декларирован константой проекта** (`CLAUDE.md`, `.cursorrules`, `README.md`), но **реализация массово отклоняется от стандарта**:
>
> - Словарная инфраструктура (`useLanguage().t(key)`) задействована в **46 из 1548 .tsx-файлов** (~3%).
> - В **1224 файлах** (~79%) импортируется `useLanguage()`, но язык применяется через **тернарники** (`language === 'ru' ? ... : ...`, `isRu ? ... : ...`) — **16 494 вхождений** в коде.
> - **DB-таблица `translations` пуста** (0 ключей).
> - Словари `ru.ts` / `en.ts` — **182 ключа каждый** (синхронны), `th.ts` — 373 ключа (избыточные).
> - `th` (тайский) **частично поддержан в коде** (тернарники `isTh ? ... :`), но не в основном пайплайне.
>
> **Вывод:** систему можно использовать как «t() по словарю» только для критичных строк (~5%). 95% UI-текста живёт **жёстко в JSX как RU+EN-тернарники** — это работоспособно, но:
> - не даёт переключения через единую DB-таблицу,
> - блокирует добавление любого 3-го языка (тайский/китайский) без правки сотен файлов,
> - усложняет редактирование текста (нужен инженер, а не контент-менеджер),
> - противоречит §11 канона tone-of-voice (централизованный контроль голоса).


- Реальный вызов `t('...')` найден только в **46 файлах** (3%).

**Интерпретация:** разработчики импортируют контекст, но используют только поле `language` для тернарников.

```tsx
// ✅ Канон
newErrors.firstName = t('auth.errors.firstName_required');
// + ключ auth.errors.firstName_required в ru/en/th.ts
```

## 3 · Поддержка тайского

### 3.1 Состояние

- `LanguageContext` корректно поддерживает `th` как первый класс.
- `th.ts` существует с **373 ключами** (но рассинхронен с RU/EN).
- В коде встречается **`isTh ? ... :`** — частичная ручная поддержка.
- DB-таблица `translations` имеет колонку `value_th` — готова к использованию.

### 3.2 Gap

- Для основной массы UI (16 494 тернарника) **тайская версия отсутствует**. Пользователь с `language=th` увидит EN-fallback (или хуже — будет `isRu ? ru : en`, и язык вообще не сработает).
- Критично для **гайд-страниц** (`/info/*`, `/legal/*`, `/visa/*`), где тайская юр. локализация — формальное требование.
