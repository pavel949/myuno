# Taxonomy Spine v2

> **Status:** Wave A (foundation) — landed 2026-06-27.
> **Owner:** Pavel (DRI). **Source files:** `src/lib/taxonomies/spine.ts`, `src/lib/taxonomies/spine/adapters.ts`.
> **Audit origin:** 2026-06 taxonomy audit (see chat history).

## Why

The 2026-06 audit found **6 parallel registries** describing the same 60 micro-apps with diverging shape (`appRegistry.ts`, `catalog/taxonomy.ts`, `verticalGroups.ts`, `clusterCatalog.ts`, DB enums, plus DB `category_groups`/`categories`). Spine is the single forward-looking SSOT that normalises all of them into one node shape and lets us measure drift instead of arguing about it.

## Model

```
SpineAppNode
├── id            SpineAppId (= keyof APP_REGISTRY)
├── surface       'arrive' | 'live' | 'manage' | 'invest' | 'legal' | 'build'
├── jtbd          JtbdClusterId[]   (A..J, from Master Taxonomy v1.0)
├── personas      PersonaCode[]     (P01..P25)
├── readiness     'ready' | 'lead_only' | 'preview' | 'hidden' | 'parked' | 'deprecated'
├── monetization  'commission' | 'subscription' | 'lead_fee' | 'capital_advisory' | 'free' | 'unknown'
├── route         string
├── leadTable?    string  (set in Wave B)
└── source        ('appRegistry' | 'catalogTaxonomy')[]
```

### Readiness — six states (§15.5 of the audit)

| State        | Meaning                                                  |
|--------------|----------------------------------------------------------|
| `ready`      | Full UX + booking/lead flow live.                        |
| `lead_only`  | Visible, captures lead only (no e2e flow).               |
| `preview`    | Read-only teaser / coming-soon.                          |
| `hidden`     | In code, not in nav.                                     |
| `parked`     | Intentionally paused (LifeHub honest-kill, etc).         |
| `deprecated` | Slated for removal; do not link to.                      |

## Hard rules

1. **Never edit `APP_REGISTRY` or `catalog/taxonomy` from Spine.** Spine derives — it does not own (yet).
2. **Never add a new top-level route via Spine.** Use existing surface + JTBD tag.
3. **Every node must have a non-empty `route` and a valid `surface`.** Enforced by contract test.
4. **Every `APP_REGISTRY` id must have a `SPINE` node** (no orphans). Hard-failing invariant.
5. **Untagged JTBD / persona / monetization is WARNING-ONLY in Wave A.** Becomes blocking in Wave C.

## Adding a node

In Wave A you don't add to Spine directly — you add to `APP_REGISTRY` and Spine derives automatically. Backfill JTBD/personas/monetization happens in Wave C/E via override maps (not yet introduced).

## Drift snapshot

`docs/audits/taxonomy-spine-drift.json` is regenerated by the contract test on every run. Review it during release prep; growth = scope creep.

## Wave roadmap

- **D** — Geo hierarchy (country → region → city → district) attached to nodes.
- **E** — Monetization tagging completed; Spine becomes primary SSOT; deprecate the duplicate registries.
