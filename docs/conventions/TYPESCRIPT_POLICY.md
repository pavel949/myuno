# TypeScript и ESLint: типизация

## Текущее состояние

- **tsconfig.app.json:** `strict: false`, `noImplicitAny: false` — исторически для ускорения разработки. Включение по всему проекту сразу даст сотни ошибок.
- **ESLint:** `@typescript-eslint/no-explicit-any: "warn"` — новый код не должен использовать явный `any`; в старом коде предупреждения устранять по мере касания файла.

## Рекомендуемый порядок (P1-T2)

1. **Новые файлы и модули** — писать с учётом строгой типизации (избегать `any`, типизировать параметры и возвращаемые значения).
2. **Постепенное включение strict** — включать `strict: true` и/или `noImplicitAny: true` по папкам через отдельные tsconfig (например, `src/auth/`, `src/lib/payments/`) или по мере рефакторинга.
3. **Критичные области** — в первую очередь: auth, платежи, бронирование; затем общие хуки и утилиты.

При включении strict в подпапке можно добавить в корень этой папки `tsconfig.json` с `"extends": "../../tsconfig.app.json"` и `"compilerOptions": { "strict": true }` (и включать в основной проект через references при необходимости).

## any

- В новом коде использовать конкретные типы или `unknown` + сужение типа.
- В существующем коде при добавлении логики в файл с `any` по возможности заменить на тип; иначе оставить и постепенно убирать в отдельном PR.
