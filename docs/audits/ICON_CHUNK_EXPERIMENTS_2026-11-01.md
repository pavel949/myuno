# Иконки Lucide и размер первой загрузки — результаты экспериментов (2026-11-01)

Повод: Lighthouse (prod, mobile) даёт `/property/search` 0.56–0.58 по производительности (порог 0.8). Production-сборка `main` (`10830b2a`) загружает при старте **≈ 687 КБ JS (gzip) в 10 файлах**, при бюджете проекта < 300 КБ для страницы приложения. Из них `vendor-icons` — 125 КБ, входной `index` — 283 КБ.

Причина: `manualChunks` собирает **все** иконки, используемые где-либо в приложении (1401 файл импортирует `lucide-react`), в один чанк `vendor-icons`, который предзагружается.

## Что пробовали (production-сборка, один и тот же коммит `main`)

| Вариант | Начальная загрузка (gzip) | JS-чанков в сборке | Вывод |
|---|---:|---:|---|
| Базовый (сейчас) | 687 КБ | 1 060 | — |
| 1. Без группировки иконок (`return undefined`) | **586 КБ** (−101) | **2 416** | Первая загрузка легче, но каждая иконка — отдельный файл: более чем вдвое больше чанков. Плохо для PWA-предзагрузки и числа запросов |
| 2. Два чанка по статической достижимости из входа (`vendor-icons` + `vendor-icons-lazy`) | 694 КБ (+7) | 1 061 | **Не работает:** граф зависимостей до tree-shaking считает «барель» `lucide-react` импортирующим все иконки, поэтому все они «достижимы» из входа |
| 3. Без группировки + `experimentalMinChunkSize: 20_000` | 658 КБ (−29) | 1 919 | Выигрыш мал, фрагментация остаётся (+859 чанков), вход вырастает до 380 КБ |

Ни один вариант не даёт выигрыша без заметного побочного ущерба, поэтому **конфигурация сборки не менялась**.

## Что это значит

- Чисто конфигурационным способом проблему не решить: `lucide-react` через общий «барель» делает недостижимой точную классификацию иконок до tree-shaking.
- Реальный выигрыш (≈ 100 КБ) лежит в структурных изменениях:
  1. заменить импорт `from 'lucide-react'` на прямые импорты по иконке (например, через трансформацию на этапе сборки с проверенной таблицей имён; у lucide есть переименованные иконки, поэтому нужна проверка таблицы);
  2. сократить иконки, статически подключённые реестрами/таксономиями на старте (в варианте 1 вход вырос всего на ~24 КБ gzip, то есть реально нужных на старте иконок немного).
- Кроме иконок, остальные части первой загрузки: `index` 283 КБ, `vendor-react` 58, `vendor-supabase` 53, `vendor-radix` 53, `vendor-motion` 39, `vendor-forms` 28.
- Оценка производительности страницы по Lighthouse зависит не только от JS (изображения, карты, длинные задачи). Отчёты Lighthouse из CI в этой сессии недоступны, поэтому вклад иконок в оценку 0.56 не измерен.

## Как воспроизвести

`npm run build` в чистой копии, затем измерить gzip-размер `index.html`-скрипта и всех `modulepreload`-чанков. Вариант 1: в `vite.config.ts` в ветке `lucide-react` вернуть `undefined` вместо `'vendor-icons'`.
