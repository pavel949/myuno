# Production readiness corrections

Source baseline: `be1224b5ed838bffebffddf12b127871adf41bad`. This tranche corrects the 2026-11-15 audit. Local implementation and isolated verification do not activate production.

## Financial boundaries

- Stripe amounts use ISO/provider minor units. THB has two decimals; 950 THB is 95000 satang. Existing undercharged sessions must be reconciled, never accepted by a legacy multiplier fallback.
- A signed Stripe event is checked against the persisted payment ID, session/reference, amount and currency. Order, payment and ledger transitions must serialize on the same order. A confirmed order does not bypass repair of missing payment or accounting work.
- Protected admin or explicitly appointed property/company approver may agree a negotiated price, per the owner's 2026-11-15 instruction. The scoped delegated path requires both booking-edit and finance-edit duties. No user assignment or role grant is made by these files.
- Partial receipts are not full payment or realized full-order revenue. For Stripe deposits, persist the verified receipt and an explicit reconciliation alert without setting full-paid fields, posting full-order ledger or dispatching a booking-confirmed notification.
- Property confirmation requires an explicitly linked, date-matching active inventory hold. Legacy stays may be linked only through an existing explicit order reference, never by equal dates alone. A conflict must abort the commercial transaction.
- Owner-approved manual RUB rules: administrator or explicitly delegated approver records actual RUB, agreed RUB-per-THB rate and an immutable document/reference; conversion rounds to 0.01 THB. Partial receipts retain the debt. Further unique documented receipts on the same request may complete exact full settlement. Overpayment and refunds require a separate recorded decision. No exchange-rate feed, tolerance, discount, payment account or user assignment is invented. Confirmation checks the existing agreed order total; repricing an existing order requires a separate checked workflow.
- Public nightly checkout now follows the already-implemented pricingEngine eligibility thresholds and independently rounded length/timing discounts. It derives one total and requires confirmation for conflicting tariff sources. Existing whole-baht final quote/deposit rounding is retained, not replaced with an invented monetary policy.

## Deployment boundaries

Forward SQL and security-preserving rollback must be reviewed together. Verify actual predecessor definitions, grants, applied migration state and deployed Edge Functions before activation. Missing RPCs produce an explicit unavailable response; there is no fallback to unsafe direct writes.

Operating Spaces require a verified property/team manifest and separate activation. No roles, membership, portfolio assignments or business data are generated by this correction.

## Backup boundaries

Anonymous REST export cannot certify a private database backup. Privileged export must fail on missing permissions, drift, truncation or table errors; incomplete exports must never be imported or labelled successful. Private artifacts require encryption. A row mirror is not a replacement for a tested database/Auth/Storage recovery process.
