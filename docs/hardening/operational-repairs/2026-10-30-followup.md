# Recorded rental tariffs and studio dimensions

## Problem and resulting behavior

The homepage uses HomeListingCard → homeShowcasePrice → surfaceFromProperty → propertyRentalDisplayPrice. Housing results use PropertyListingCard → the same surface selector. That selector preferred the generic amount's declared period. Detail/inquiry used propertyDetailPricing, which independently preferred an explicit nightly field for short-stay quotes. usePropertyWithRentalTerms constructs rentalTerms.price_per_night from the same public property.price_per_night; it does not obtain a separate private tariff.

Live public HTML on Oct30 showed Canvas card ฿3000/month and inquiry ฿3000 ×2 nights. Combined with that deterministic public mapping, this establishes coexisting monthly and explicit nightly tariffs; no privileged database query was made. Public HTML alone does not distinguish whether the monthly amount comes from price/price_period or price_per_month, because the old selector prefers the dedicated monthly field. That raw-column attribution is not claimed without the already-public network response; the new selector handles both sources and rejects disagreement. Generic search intentionally has no monetary offer/billing context and already emits price:null for public homes. Public list/detail projections both include price, price_period, price_per_night/month/year and currency.

The canonical recorded-rate selector now supplies both display and quote eligibility. Homepage, housing card, detail and inquiry visibly list independent nightly/monthly/yearly tariffs together when multiple rates exist. Nothing is divided, multiplied into another tariff, converted, or written to the catalog. The selected-night quote still multiplies a genuine nightly rate by nights. Multiple sources for one period must agree; conflicting same-period amounts, conflicting term currency or a priced unknown custom period suppress rates and automatic quotes. Inquiry returns to request-only detail. Empty generic money cannot hide a valid independent dedicated tariff.

Owner metadata editing now preserves bedrooms0 and bathrooms0 through hydration, unrelated edits, checked save and preview. Existing actor scope, controlled writer, revisions, permissions and RPC signatures are unchanged.

## Regression evidence

Tests exercise the actual homepage and housing cards and property detail; isolated browser flow visits homepage → housing search → detail → inquiry with the same Canvas-shaped fixture and compares both labeled tariffs. A second browser case verifies conflicting nightly sources cannot reach a payable inquiry. Owner controller regression verifies zero dimensions remain zero in the actual controlled payload and preview. Fixtures deny external requests and business writes.

Final exact-head counts are recorded in the prepared PR description after validation. No follow-up PR creation, merge or deployment is implied by this document.
