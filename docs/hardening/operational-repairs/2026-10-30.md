## Contract and scope

This is a routine authoring/presentation repair with two bounded domain corrections: listing activity must not imply sale status, and short-stay inquiry must use the same existing tariff eligibility/resolver as property detail. No new domain/table/RPC, migration, role, grant, RLS policy, inventory commitment, payment writer or deployment is introduced.

- `developers` → `property_projects.developer_id` and `properties.project_id` retain their existing identities. Project create/update invalidates the actual admin/public/owner caches. Bulk developer assignment, project approval and property linkage require the full selected ID set and intended stored fields in the returned rows. Partial mutation can already have occurred; the error explicitly requires reload/review and does not claim rollback.
- Provider/service/property/developer deletes and sales-inventory mutations require a single returned row. Sales-inventory update/delete also filters the selected project ID. A SELECT/RLS denial is an unconfirmed result, never success. No permissions are widened to satisfy readback.
- Physical-property authoring remains `properties`; sales inventory remains `project_units`. The existing admin project tab continues to create physical listing rows, now pending review and inactive by default. Its `is_active` flag is labelled listing activity, never sold/reserved. Ground floor and studio zero bedrooms are preserved. These are not a bridge migration or proof of a complete building/unit workflow.
- Services, project properties, sales units, inquiry property and newbuild KPI reads expose failure separately from empty/zero. KPI counts fail on query error/missing count; no all-clear is inferred.
- Inquiry uses `propertyDetailPricing`, including dedicated nightly terms, explicit billing period, rental eligibility, tenancy and supported currency. Monthly/unknown legacy prices are not multiplied by nights. Explicit dedicated nightly rates remain valid even where a separate monthly tariff exists. No actual commercial rate is changed or inferred.
- House rules and inquiry use the existing `CANCELLATION_POLICY_DETAILS` text. Strict means the stored seven-day partial-refund description, not automatically non-refundable. This is display consistency, not a change to refund execution.
- Global `/search` query and category are URL-backed. Result links carry the existing validated public journey origin; `/search` is added to the narrow return allowlist. Existing property/offplan/area behavior stays in that helper. Private/external return targets remain rejected.
- `NbLeadForm` locks double submissions and stores a random primary-key attempt ID under a SHA-256 digest of the normalized payload in sessionStorage before writing. Same-tab retries/reloads use that same ID. Storage failure blocks the write. Only the existing acknowledged insert is success; a duplicate constraint response is explicitly unconfirmed. No contact details are stored by this helper. **This is not cross-tab/server-authoritative idempotency, a durable receipt/readback API, or production acceptance.** Attribution is still best effort and is not transactionally coupled to lead insertion.
