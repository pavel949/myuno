## Catalogue RLS (0043)

Historical [20260121011023](https://github.com/pavel949/myuno/blob/main/supabase/migrations/20260121011023_7e3264c9-ee98-4884-9bde-f85cd26f0cfa.sql) introduced approved+active or mapped owner reads. Original broad policies were not removed. Permissive policies OR together, including `FOR ALL`. This candidate drops the original broad names, normalizes the approved/owner policy and adds a restrictive SELECT ceiling, preserving approved+active public reads, provider owner (`providers.id = row.provider_id` AND `providers.user_id = auth.uid()`) and protected platform admin (`has_role(...,'admin')`). It refuses to run if the expected RLS/role helper/approved policies or 0042 trigger are missing. `uno_team` alone gets no private/global reads, consistent with [0032](https://github.com/pavel949/myuno/blob/main/drizzle/migrations/0032_catalog_notification_private_boundaries.sql). A superadmin must actually carry the protected admin capability; do not assume a UI role name or profile attribute confers DB rights. No grants or changes to INSERT/UPDATE/DELETE policies. In particular legacy legal_services UPDATE permits admin/uno_team in historical source; existing write paths are outside this read patch, need separate authority review and positive/negative tests. Do not confer global uno_team reads merely to restore moderation. Restrictive read ceiling may affect UPDATE/DELETE operations relying on SELECT; test authorized workflows. Public approved full rows may still expose phone/email or moderation fields: a reviewed public projection with explicit field allowlist is a separate privacy requirement; this patch does not certify column privacy. Audit views, RPCs (especially SECURITY DEFINER), table grants and all consumer queries, not just direct table reads.

The PR #344 author reported a public API count on 24 Nov (not independently remeasured): gyms 18 total / 10 approved active / 3 active pending / 5 inactive; legal_services 14 / 2 / 7 / 5. Ten active unapproved entries need a human decision; do not auto-approve. Verify fresh aggregate counts with permission. No data rows changed.

## Intake privacy: separately gated cutover

[Original migration](https://github.com/pavel949/myuno/blob/main/supabase/migrations/20260131114433_17ea5ab2-0cb5-4e88-8e45-616c4a4c882a.sql) creates intake-uploads public=true with authenticated upload/delete based on profiles.user_type and a public read policy. Need live flag and protected role/grant verification, not real file access. [useIntakeAgent](https://github.com/pavel949/myuno/blob/main/src/hooks/useIntakeAgent.ts) lines 117–167 upload `intake/timestamp-originalName`, derive `getPublicUrl`, send `uploadedImages` to [intake-listing-agent](https://github.com/pavel949/myuno/blob/main/supabase/functions/intake-listing-agent/index.ts). Edge checks authenticated user + staff gate, builds items, stores sourceImages and uploaded_images in ai_intake_sessions; approval code and [validateItem](https://github.com/pavel949/myuno/blob/main/src/lib/intake/validateItem.ts) can reuse sourceImages as catalogue images. Flipping bucket now breaks these URLs; issuing signed URLs and saving them in public records is also wrong.

Proposed staged SQL is intentionally **not registered**. It removes named legacy intake policies; direct access only protected admin + actor-owned UUID-prefixed key (SELECT/INSERT/DELETE); forbids direct UPDATE, including move into/out of intake through that policy; no blanket staff reads or profile metadata claims. Restrictive ceilings stop permissive policy fallback. Does not change bucket flag. Before any approval:

1. Inventory historical references in ai_intake_sessions (items/uploaded_images), extracted fields, galleries, cover_image, storage URL paths, persisted logs/exports, public catalogue. Aggregate/count only, no copying actual customer files. Classify source docs versus approved public media. Identify ownerless and legacy intake/ keys, consumers and ownership; preserve them with a reviewed server-controlled migration/ACL, no invented owner backfill. No deletion of real files.
2. Implement compatible versioned frontend + Edge contract: actor-bound opaque UUID key, upload with upsert=false, content-type/size validation; send storage key not arbitrary URL; verify JWT + protected capability + exact actor/session/object authorization with actor-scoped storage client; if necessary resolve private objects server-side with a narrowly scoped short-lived signed URL/authorized download only for processing. No signed URL/public raw intake URL in persistent sessions, logs, or catalogue; reject foreign keys, arbitrary external URLs in the file mode and spoofed owner IDs. Preserve compatible readers of verified historical refs, no permissive public fallback. Return session receipt only if persisted; verify errors/retry, partially uploaded files and processing of actual PDF/image formats; document authorized AI data processing and retention. Existing Edge staff gate is not automatically the same as protected admin; align permissions deliberately. New UI/Edge code is not implemented in this SQL package.
3. Only explicitly selected public listing media may be promoted through reviewed server copying into intended public media bucket, with a stable public key. Never use raw source documents, legacy or signed intake URLs as listing images; reject them at publishing boundary as well as client mapping. Verify existing listings still display intended media and do not expose source files.
4. Test both old/new client versions in isolated full Supabase, stage versioned API, stage restrictive intake policies (still public URL until bucket flip). Freeze legacy upload path only at controlled cutover; confirm updated consumers no longer require public URLs, then set `public=false` via supported Storage bucket update API in an authorized change window. Verify unauthenticated direct URL/transform/download/HEAD denied, prior cached URLs and signed links expire or are invalidated as supported; historical already downloaded copies cannot be recalled. Verify admin authorized processing, other users/uno_team denied and legitimate owners retain approved access. Do not declare confidentiality just from RLS.
