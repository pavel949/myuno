# Модель зрелости myUNO — 4 уровня по каждой оси

**Назначение:** не одна цифра 1–5, а **четыре ступени (L1→L4)** на ось с явными критериями. Текущая позиция — **жирным**.

---

## 1. Продукт / рынок

| Уровень | Название | Критерии |
|--------|----------|----------|
| **L1** | Идея / прототип | Нет стабильного пользовательского контура, нет метрик. |
| **L2** | Pre-PMF | Есть активные пользователи **или** чёткая метрика «северной звезды», **цель — первая транзакция / первые 100 MAU** (как в `CLAUDE.md`). |
| **L3** | Ранний PMF | Повторяемые транзакции, удержание, понятный канал роста (хотя бы в нише). |
| **L4** | Масштабирование | Предсказуемый unit-economics, несколько сегментов, playbook онбординга. |

**Сейчас myUNO:** **L2** — Pre-PMF, фокус на первой транзакции и валидации.

---

## 2. Инженерия и релиз

| Уровень | Название | Критерии |
|--------|----------|----------|
| **L1** | Ручной хаос | Деплой вручную, нет единого pipeline. |
| **L2** | Базовый CI | Сборка/линт частично; нет typecheck или тесты нестабильны. |
| **L3** | Стандартизированный pipeline | **Lint → typecheck → unit tests → production build** на main/PR; env для CI; структура `hooks` / `APP_ROUTES`. |
| **L4** | Release engineering | Preview deploys, feature flags в проде, rollback playbook, метрики сборки (время, flaky tests ≈ 0). |

**Сейчас myUNO:** **L3** — CI полный цикл + `typecheck`, Vercel, документация env.

---

## 3. Качество кода / типизация

| Уровень | Название | Критерии |
|--------|----------|----------|
| **L1** | Нет дисциплины | Нет общих правил TS/ESLint на репо. |
| **L2** | Минимум | TS в проекте, но **`strict: false`**, много `any`, долг. |
| **L3** | Управляемый долг | Линтер, **logger**, точечные модули строже (`typecheck:strict-null`, `dealAuditEncoding` и т.д.), рефакторинг критичных путей. |
| **L4** | Строгая база | `strict` или эквивалент на всём `src`, `noImplicitAny` для нового кода, снижение `any` по метрике. |

**Сейчас myUNO:** **между L2 и L3** → в таблице ниже условно **L2+** (ближе к L3 за счёт CI typecheck и локальных практик).

---

## 4. Тестирование

| Уровень | Название | Критерии |
|--------|----------|----------|
| **L1** | Почти нет | Только ручные проверки. |
| **L2** | Инструменты есть, покрытие низкое | Vitest/Playwright подключены, **мало тестов относительно объёма** (~14 unit-файлов при большом `src/`). |
| **L3** | Критичные пути | Happy-path e2e или интеграционные тесты на **оплату, MC/CRM, auth**; CI зелёный обязателен. |
| **L4** | Широкое покрытие | Покрытие по метрике или по слоям (hooks, критичные edge functions), контрактные тесты API. |

**Сейчас myUNO:** **L2** — инфраструктура есть, покрытие не дотягивает до L3.

---

## 5. Безопасность (модель)

| Уровень | Название | Критерии |
|--------|----------|----------|
| **L1** | Нарушения базы | Секреты в клиенте, RLS выключен. |
| **L2** | Базовая гигиена | Anon key на клиенте, **RLS включён**, чувствительная логика в Edge Functions. |
| **L3** | Паттерны и защита | **Санитизация**, CORS-документ, `mc_can_access()` для MC, нет service role во frontend. |
| **L4** | Управляемая безопасность | Регулярный аудит RLS/SQL, секрет-сканирование, ужесточение CORS для критичных функций, threat model по ключевым потокам. |

**Сейчас myUNO:** **между L3 и L4** → **L3+** (сильная модель, полный аудит RLS и hardening — ещё впереди).

---

## 6. Операции / наблюдаемость

| Уровень | Название | Критерии |
|--------|----------|----------|
| **L1** | Ничего | Узнаём о проблемах от пользователей. |
| **L2** | Деплой + логи по умолчанию | Vercel/Supabase логи, без единой стратегии алёртов. |
| **L3** | Осознанный ops | Дашборды ошибок (Sentry/аналог **или** дисциплина просмотра edge logs), on-call понятен хотя бы основателю. |
| **L4** | SRE-lite | Алёрты по SLO, runbooks, postmortem культура. |

**Сейчас myUNO:** **L2** — деплой есть, **явного SRE/алёртинга в доках мало**.

---

## 7. Коммерция / доверие

| Уровень | Название | Критерии |
|--------|----------|----------|
| **L1** | Нет денег в продукте | Платежи не интегрированы. |
| **L2** | Интеграция без доказательства | **Stripe в стеке**, env описаны, но **сквозной «боевой» цикл не зафиксирован** как факт. |
| **L3** | Доказанные деньги | Есть **реальные** успешные транзакции, возвраты/чеки по процессу, понятная эскалация. |
| **L4** | Коммерческая зрелость | Юр. пакет (оферта, privacy), лимиты Stripe, сверка с бухгалтерией, chargeback-процесс. |

**Сейчас myUNO:** **L2** — платежи в архитектуре, коммерческое доказательство — следующий рубеж.

---

## Сводная таблица (4 уровня + позиция)

| Ось | L1 | L2 | L3 | L4 | **Сейчас** |
|-----|----|----|----|----|------------|
| Продукт / рынок | идея | **Pre-PMF** | ранний PMF | масштаб | **L2** |
| Инженерия и релиз | ручной | частичный CI | **полный CI+typecheck** | release eng | **L3** |
| Код / типизация | нет правил | strict off | управляемый долг | strict везде | **L2–L3** (≈ **L2+**) |
| Тестирование | нет | **мало тестов** | критичные пути | широкое покрытие | **L2** |
| Безопасность (модель) | критично | база | **паттерны RLS/CORS** | аудит+hard | **L3** (≈ **L3+**) |
| Операции / наблюдаемость | нет | **деплой+логи** | алёрты/runbook | SRE-lite | **L2** |
| Коммерция / доверие | нет оплат | **Stripe без доказ. цикла** | реальные платежи | юр+процессы | **L2** |

---

## Как «дотянуть» оси до следующего уровня (кратко)

| С L2 → L3 | С L3 → L4 |
|-----------|-----------|
| Продукт: первая и повторяемая транзакция | Масштабируемый рост и экономика |
| Тесты: happy-path e2e MC + checkout | Покрытие и контракты |
| Ops: один инструмент ошибок + weekly review логов | Алёрты и runbooks |
| Коммерция: один задокументированный успешный платёж | Юр. пакет и процессы возвратов |
| Код: `strictNullChecks` на новых модулях | `strict` на всём `src` |
