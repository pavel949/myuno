# Резорты и гостиницы: категории номеров, тарифы и правила

## Что меняется для пользователей
- Объект может быть не только отдельным кондо, но и **резортом или гостиницей**: у него есть **категории** (например, «Делюкс с видом на море», «Вилла с бассейном»), а в каждой категории — конкретные номера.
- Цены, сезоны, цены на отдельные даты и правила (минимальный срок, запрет заезда/выезда, закрытие продаж) задаются **на категорию**. При необходимости их можно уточнить для отдельного номера.
- **Тарифы** для категории: например, «Возвратный», «Невозвратный −10%», «С завтраком +500 ฿», «Раннее бронирование». У каждого тарифа своя политика отмены и свои ограничения.
- Гость выбирает категорию и тариф, а не конкретный номер. Сервер сам назначает свободный номер. Менеджер может сменить номер в PMS.
- Кондо и виллы работают как сейчас: объект без категорий бронируется напрямую.

## Структура

```text
Объект (резорт / гостиница / кондо)
 ├─ Категория номеров ── тарифы, сезоны, цены на даты, ограничения
 │    └─ Номер 101, 102 … (каждый — свой календарь, уборка, PMS)
 └─ (у кондо категорий нет — как сейчас)
```

Порядок расчёта цены за ночь (одинаковый на странице и на сервере):
цена номера на дату → сезон номера → цена категории на дату → сезон категории → базовая цена категории → поправка тарифа (скидка, доплата).

## Этапы
1. **Данные.** Категории, связь номеров с объектом и категорией, тарифы, ограничения по датам. Сезоны и цены на даты получают привязку к категории. Всё за флагом `feature_flag:multi_unit_properties`, с описанием отката.
2. **Расчёт и бронирование.** Общий расчёт цены учитывает категорию и тариф. Доступность категории = номера минус занятые. Серверная проверка суммы и назначение номера при оплате. Двойное бронирование одного номера невозможно.
3. **Кабинет управления.** Страница «Структура объекта» (категории и номера), таблица цен «категория × даты», редактор тарифов и ограничений.
4. **Страница объекта для гостя.** Список категорий с ценой, наличием, тарифами и условиями отмены.
5. **Проверка.** Тестовый резорт [TEST] с двумя категориями и тремя номерами: бронь по категории, назначение номера, сумма совпадает на странице, на сервере и в календаре; затем удаление тестовых данных.

## Технические детали
- Новые таблицы: `property_room_categories` (property_id, названия RU/EN, вместимость, кровати, площадь, удобства, базовая цена, min_stay, фото), `property_rate_plans` (category_id, тип поправки %/фикс, питание, политика отмены, min/max stay, срок до заезда, активность), `property_stay_restrictions` (category_id или property_id, дата, min_stay, closed_to_arrival, closed_to_departure, stop_sell).
- `properties`: новые nullable-колонки `parent_property_id`, `room_category_id`, `property_kind` (`unit`|`resort`|`hotel`, по умолчанию `unit`). Номер — обычная строка `properties`, поэтому календарь, iCal, уборки, PMS и `property_bookings` работают без изменений.
- `property_rate_seasons` и цены на даты: nullable `category_id`.
- `orders.metadata` / позиция заказа: `room_category_id`, `rate_plan_id`, разбивка цены по ночам (заодно закрывает ограничение «не видно цену каждой ночи»).
- SECURITY DEFINER RPC `assign_room_for_category(category_id, dates)` с блокировкой строки; вызывается только сервером оплаты (service_role).
- `_shared/property-quote.ts` и клиентский расчёт расширяются одним общим модулем; новые тесты на тарифы и ограничения.
- RLS: чтение категорий/тарифов — только у активных объектов; изменение — `can_manage_property`. GRANT на каждую новую таблицу.
- Без DROP и без переименований; откат в `docs/hardening/rollback/`.

## Вопросы, решённые по умолчанию (можно поправить)
- Номер = строка `properties` (а не отдельная таблица). Рекомендую: так сохраняется всё, что уже работает для кондо.
- Гость бронирует категорию, номер назначает система.
- Валюта — только THB, задаток 10%, как сейчас.
