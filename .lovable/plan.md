
# Аудит Процесса Обработки Заказов: Текущее Состояние и План Доработок

## Текущее состояние ("Как сейчас")

### Что работает

| Этап | Статус | Детали |
|------|--------|--------|
| Создание заказа | Работает | `create_order_atomic` RPC создает запись в `orders` + `order_items` + `order_participants` + `order_addresses` |
| Email админу | Работает | `notify-admin-order` отправляет красивое HTML-письмо на pavel@ignatevestate.com с деталями заказа |
| WhatsApp админу | Работает | Через UltraMsg API (если настроен) или лог в консоль |
| Email клиенту | Работает | `send-order-email` отправляет "Ваш заказ принят" клиенту |
| In-app уведомление клиенту | Работает | Запись в таблицу `notifications` |
| Личный кабинет клиента | Работает | Страница `/bookings` показывает список заказов, `/bookings/:id` показывает детали |
| Трекинг заказа | Работает | `/orders/:id/tracking` с прогресс-баром и таймлайном |

### Критические пробелы (что НЕ работает)

| # | Проблема | Влияние |
|---|----------|---------|
| 1 | **Админка: нет карточки заказа** -- кнопка "Глаз" в таблице OperationsBookingsTab ничего не делает (нет onClick) | Админ не может посмотреть детали заказа |
| 2 | **Админка показывает только `bookings`, а не `orders`** -- OperationsBookingsTab запрашивает таблицу `bookings`, тогда как все новые заказы идут в `orders` | Новые заказы вообще не видны в админке |

| 5 | **Email админу не содержит адреса доставки** -- поле `addresses` передается, но не рендерится в HTML | Потерянная информация при пересылке поставщику |
| 6 | **Нет "Forward to Supplier" функции** | Нельзя переслать карточку заказа поставщику из админки |

## План доработок

### 1. Админ-панель: Полноценный хаб заказов (вместо bookings)

Переписать `OperationsBookingsTab` чтобы он показывал данные из таблицы `orders` (а не `bookings`), так как все новые заказы через BookingWizard попадают именно туда.

- Запрос к `orders` с join на `order_items`, `order_participants`, `order_addresses`
- Колонки: Номер заказа, Тип, Клиент, Телефон, Дата, Сумма, Статус, Действия
- Фильтры по статусу: pending, confirmed, in_progress, completed, cancelled

### 2. Детальная карточка заказа (Sheet/Drawer)

Создать новый компонент `AdminOrderDetailSheet` -- боковая панель, которая открывается при клике на заказ:

**Содержимое карточки (максимально подробное для пересылки поставщику):**
- Номер заказа + дата создания
- Тип заказа с иконкой
- Статус с цветным badge
- Блок "Клиент": имя, телефон (кликабельный), email
- Блок "Состав заказа": таблица позиций (название, количество, цена)
- Блок "Дата и время": когда запланировано
- Блок "Адреса": pickup / dropoff если есть
- Блок "Примечания": заметки клиента
- Итого: сумма, валюта, способ оплаты

**Кнопки действий:**
- "Подтвердить" (pending -> confirmed)
- "В работу" (confirmed -> in_progress)
- "Завершить" (in_progress -> completed)
- "Отклонить" с полем причины (-> cancelled)
- "Скопировать для поставщика" -- копирует форматированный текст заказа в буфер обмена
- "Отправить поставщику в WhatsApp" -- открывает WhatsApp с предзаполненным сообщением

### 3. Уведомление клиенту при смене статуса

Создать edge function `notify-order-status-change`:
- При подтверждении: email + in-app "Ваш заказ #XXX подтвержден!"
- При отклонении: email + in-app "К сожалению, заказ #XXX отклонен. Причина: ..."
- При завершении: email + in-app "Заказ #XXX выполнен! Спасибо!"

### 4. Обогатить email админу адресами и контактами

Добавить в HTML-шаблон `notify-admin-order`:
- Блок адресов (pickup/dropoff)
- Способ оплаты
- Кнопка "Ответить клиенту" (mailto)
- Кнопка "Открыть в админке"
