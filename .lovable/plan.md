

# Редизайн Airport Transfer: пошаговый flow в стиле Grab/Bolt

## Проблема

Сейчас страница трансфера -- это одна длинная форма (~970 строк) со всеми полями на одном экране. Пользователь видит 10+ полей сразу и не понимает порядок действий. По данным сессии, пользователь отметил "странно работает" -- особенно при переключении маршрутов и типов авто.

## Как делают лучшие приложения

Grab, Bolt и Uber используют **пошаговый flow с визуальной обратной связью**:

1. **Шаг 1 -- Маршрут**: Выбор направления (из/в аэропорт) и адреса. Сразу видна карточка маршрута с расстоянием/временем
2. **Шаг 2 -- Автомобиль**: Горизонтальный список машин с ценами, привязанными к выбранному маршруту. Цена обновляется мгновенно
3. **Шаг 3 -- Детали и оплата**: Рейс, дата/время, контакты, способ оплаты. Минимум полей, автозаполнение из профиля

Ключевые принципы:
- **Цена видна всегда** -- sticky-панель внизу с ценой обновляется при любом изменении
- **Прогресс виден** -- step indicator наверху (3 точки/шага)
- **Каждый шаг компактен** -- помещается на один экран без скролла
- **Обратная связь** -- при выборе маршрута сразу показывается время в пути и цена для всех типов авто

## Решение для myUNO

Разбить текущую монолитную форму на **3-шаговый wizard** внутри того же файла:

## Технические изменения

### Файл: `src/pages/transport/AirportTransferBooking.tsx`

**1. Добавить step-state и step indicator**
- `const [step, setStep] = useState(1)` (3 шага)
- Компактный индикатор прогресса наверху (3 точки с линиями)
- Анимация перехода между шагами через framer-motion `AnimatePresence`

**2. Шаг 1 -- Маршрут (Direction + Terminal + Destination)**
- Направление: toggle из/в аэропорт (оставить как есть)
- Терминал: 2 кнопки (оставить)
- Адрес назначения: популярные маршруты как карточки (2 колонки вместо горизонтального скролла) + автокомплит для кастомного адреса
- Каждая карточка маршрута показывает: название, время в пути, базовую цену
- Кнопка "Далее" активна только когда выбран терминал + адрес

**3. Шаг 2 -- Автомобиль (Vehicle Selection)**
- Вертикальный список карточек автомобилей (не горизонтальный скролл)
- Каждая карточка: иконка, название, вместимость, рассчитанная цена для выбранного маршрута
- Цена для каждого авто = `route.base_price * vehicle.price_multiplier`
- Выбранное авто подсвечивается
- Кнопка "Далее" активна когда выбрано авто

**4. Шаг 3 -- Детали и оплата**
- Компактная сводка маршрута наверху (откуда -> куда, авто, цена)
- Поля: номер рейса, дата/время, пассажиры/багаж (в одной строке)
- Контакты: автозаполнение из профиля (имя, телефон, email в компактной форме)
- Имя на табличке (только для from-airport)
- Примечания (опционально)
- Способ оплаты: 3 кнопки (карта, наличные, myUNO)
- CTA кнопка: "Забронировать за ฿X"

**5. Sticky bottom bar**
- Всегда показывает: выбранный маршрут, тип авто, итоговую цену
- Кнопка меняется: "Далее" на шагах 1-2, "Забронировать/Оплатить" на шаге 3
- Кнопка "Назад" (стрелка) на шагах 2-3

**6. Исправить баг в консоли**
- `AddressAutocomplete` не обёрнут в `forwardRef` -- добавить

### Без изменений
- Логика создания заказа (`handleSubmit`) -- остаётся
- Экран успеха -- остаётся
- Fast Track upsell banner -- переносится на шаг 3
- Динамическое ценообразование -- формула та же, просто лучше визуализирована
