
# Аудит консистентности сборки myUNO

## Общая оценка: 🟡 Хорошо с замечаниями

Проект имеет солидную архитектуру с унифицированными компонентами, но выявлены несколько зон неконсистентности, требующих исправления.

---

## 1. Архитектурная консистентность

### Положительные аспекты

| Компонент | Статус | Примечание |
|-----------|--------|------------|
| `MiniAppLayout` | ✅ Консистентно | Используется во всех вертикалях |
| `UnifiedHeader` | ✅ Консистентно | Sticky header с backdrop-blur |
| `UnifiedFilterRibbon` | ✅ Консистентно | Единый паттерн категорий |
| `ItemCard` | ✅ Консистентно | horizontal/vertical варианты |
| `FilterConfig` структура | ✅ Консистентно | Единый интерфейс для фильтров |
| `filterUtils.ts` | ✅ Консистентно | Общие функции для нормализации |
| `designTokens.ts` | ✅ Консистентно | Единый источник стилей |

### Выявленные проблемы

| Проблема | Вертикаль | Критичность |
|----------|-----------|-------------|
| Property не использует `MiniAppLayout` | Недвижимость | 🟠 Средняя |
| Experiences использует кастомный `ExperienceCard` вместо `ItemCard` | Опыт | 🟡 Низкая |
| Market использует кастомный `ProfessionalProductCard` вместо унифицированного | Маркетплейс | 🟡 Низкая |

## 2. Консистентность хуков (Data Layer)

### Паттерны использования хуков

```text
┌─────────────────────────────────────────────────────────────┐
│  Pattern 1: useSupabaseQuery (РЕКОМЕНДУЕТСЯ)               │
│  Используют: useYachts, useSalons, useVehicles, useEvents  │
│  ✅ Стандартный паттерн с QueryFilter[]                     │
├─────────────────────────────────────────────────────────────┤
│  Pattern 2: useQuery + custom fetch                         │
│  Используют: useTours, useExperiences, useProperties       │
│  ✅ Допустимо для сложных запросов                          │
├─────────────────────────────────────────────────────────────┤
│  Pattern 3: useState + useEffect (УСТАРЕВШИЙ)              │
│  Используют: useBouquets                                    │
│  ⚠️ Требует миграции на useQuery                            │
└─────────────────────────────────────────────────────────────┘
```

### Выявленные несоответствия

| Hook | Проблема | Исправление |
|------|----------|-------------|
| `useBouquets` | Использует useState/useEffect вместо react-query | Мигрировать на `useQuery` |
| `useHomeServices` | Новые поля не загружаются | Добавить `provider_type`, `has_insurance`, `response_time_minutes` |
| `useRestaurants` | `searchQuery` в фильтрах некорректно использует operator 'or' | Использовать стандартный `ilike` pattern |

## 3. Консистентность фильтров

### Сводная таблица фильтров по вертикалям

| Вертикаль | FilterConfig | Price Level | Multi-select | Синхронизация с БД |
|-----------|-------------|-------------|--------------|-------------------|
| Рестораны | `deliveryFilterConfig` | ✅ | ✅ | ✅ |
| Красота | `beautyFilterConfig` | ✅ | ✅ | ✅ |
| Яхты | `yachtFilterConfig` | ✅ | ✅ | ✅ |
| Транспорт | `transportFilterConfig` | ✅ | ✅ | ✅ |
| Опыт | `experienceFilterConfig` | ✅ | ✅ | ✅ |
| Цветы | `flowerFilterConfig` | ✅ | ✅ | ✅ |
| Дом.услуги | `servicesFilterConfig` | ✅ | ✅ | ✅ (после рефакторинга) |
| Недвижимость | `propertyFilterConfig` | ⚠️ Dynamic | ✅ | ✅ |

### Проблема: Недвижимость использует динамические фильтры

В отличие от других вертикалей, `PropertyIndex` загружает опции фильтров из `usePropertyFilterOptions()`, что создаёт async зависимость. Это **допустимо**, но отличается от статического паттерна остальных вертикалей.

|-----------|-------------------|---------|-----------------|

3. **ProfessionalProductCard** — можно оставить, т.к. специфичен для e-commerce (quantity controls)

## 5. Консистентность таксономии категорий

### Источники правды

| Вертикаль | Источник таксономии | Статус |
|-----------|---------------------|--------|
| Дом.услуги | `homeServicesTaxonomy.ts` | ✅ Единый |
| Опыт | `experience_categories` (DB) | ✅ Динамический |
| Маркетплейс | `marketplace_categories` (DB) | ✅ Динамический |
| Рестораны | Статичные `CUISINE_CATEGORIES` | ⚠️ Не в БД |
| Красота | Статичные `SERVICE_CATEGORIES` | ⚠️ Не в БД |
| Яхты | Статичные `YACHT_CATEGORIES` | ⚠️ Не в БД |

### Рекомендация

Для полной динамичности можно мигрировать статичные категории в `lookup_values`, но это **опционально** — текущий подход работает.
