

# Упрощение установки PWA на мобильный — план

## Проблема (что сейчас)

На пути «увидел сайт → иконка на главном экране» у пользователя **5–7 шагов** и две причины, почему иконка может «не появиться».

### Сейчас флоу выглядит так:

**Android Chrome (нативный prompt доступен):**
1. Заходит на сайт → видит маленький `InstallBanner` сверху (легко проигнорировать).
2. Через **45 секунд** появляется `MobileInstallSheet` (drawer снизу).
3. Жмёт «Установить» → появляется системный диалог Chrome.
4. Подтверждает → иконка добавлена.
   - **2 экрана + 1 системный диалог = 3 клика.**

**Android Chrome (prompt НЕ сработал) или iOS Safari:**
1. Видит баннер → жмёт «Установить» → открывается `/install`.
2. На `/install` жмёт большую кнопку «Показать инструкцию».
3. Открывается `IOSInstallGuide` / `AndroidInstallGuide` — модалка с **3 шагами**, у каждого кнопка «Далее».
4. Закрывает гайд → **сам идёт в меню браузера** → Share → Add to Home Screen → подтвердить.
   - **2 экрана + 3 шага гайда + 3 ручных шага в браузере = до 8 кликов.**

### Почему «иконка не появляется»

1. **iOS Safari**: после «Add to Home Screen» иконка ВСЕГДА появляется на домашнем экране — но если пользователь использовал **Chrome/Firefox на iPhone**, опции просто нет (на iOS все браузеры — обёртки над WebKit без PWA install). Сейчас мы это упоминаем мелким текстом внизу, а не **первым делом**.
2. **Android**: если `beforeinstallprompt` уже отстрелил один раз и пользователь его отклонил, повторно мы только показываем гайд «нажмите ⋮» — но в Chrome пункт «Установить приложение» появляется в меню только когда соблюдены **PWA install criteria** (валидный manifest, SW, https, ≥30 сек на сайте). Если критерии не сошлись — пункта в меню нет, инструкция вводит в заблуждение.
3. **Иконка-плейсхолдер для maskable**: в манифесте указано `purpose: 'any maskable'` для 192/512 — но фактически файлы НЕ нарисованы как maskable (без safe zone 80%). На некоторых лаунчерах Android иконка обрезается в круг и выглядит «пустой».
4. **Скриншоты-плейсхолдеры**: `mobile-home.png` и `mobile-services.png` — оба 10343 байта (одинаковые файлы-заглушки 1080×1920 с одним пикселем). Chrome, увидев это, может не показать богатый install UI.
5. **iOS apple-touch-icon размер**: основной apple-touch-icon — 180×180 PNG. Это правильно, но он шарится с обычной иконкой — на iOS под маску обрезается без safe zone, выглядит как «пустой квадрат».

## Что меняем

### A. Убираем лишний экран `/install` для нативного prompt

**Сейчас:** Banner → клик «Установить» → редирект на `/install` → ещё клик на «Установить приложение» → системный диалог.

**Станет:** Banner / Sheet → клик «Установить» → **сразу системный диалог** (если `canInstall === true`). Никаких промежуточных экранов.

- В `InstallBanner.tsx` (уже почти так — вызывает `install()` напрямую), но `MobileInstallSheet.tsx` тоже вызывает `install()` напрямую — это уже OK.
- Новое: после успешной установки показывать **toast** «Готово! Иконка на главном экране» + автоматически прятать banner навсегда.

### B. Объединяем `Install.tsx`, `IOSInstallGuide`, `AndroidInstallGuide` в один экран

Сейчас три компонента и три разных дизайна. Делаем один экран `/install` с **одной кнопкой и одним контекстным блоком инструкции под ней** (без модалок и шагов «Далее/Назад»).

**Структура нового `/install`:**

```text
┌──────────────────────────────────┐
│  [иконка myUNO 96px]             │
│  Установить myUNO                 │
│  ~2 МБ · бесплатно                │
│                                   │
│  ┌─────────────────────────────┐ │
│  │   📲 Установить             │ │ ← если canInstall: системный prompt
│  └─────────────────────────────┘ │ ← иначе: скролл к инструкции ниже
│                                   │
│  ─── Как это работает ───         │
│  [3 буллета преимуществ]          │
│                                   │
│  ─── Если кнопка не сработала ─── │
│  Платформа определяется автомат.  │
│                                   │
│  iOS Safari (показ если isIOS):   │
│   1. Нажмите [Share icon]         │
│   2. «На экран Домой»             │
│   3. «Добавить»                   │
│                                   │
│  Если у вас Chrome на iPhone:     │
│   ⚠️ Откройте сайт в Safari —     │
│   у Chrome на iPhone нет этой     │
│   функции. [Кнопка: Открыть в Safari]│
│                                   │
│  Android Chrome:                  │
│   1. Нажмите ⋮ в правом верхнем  │
│   2. «Установить приложение»      │
│   3. Подтвердите                  │
└──────────────────────────────────┘
```

Никаких модалок с «Далее/Назад/Понятно!» — пользователь читает 3 строки и сразу делает.

### C. Удаляем `IOSInstallGuide.tsx` и `AndroidInstallGuide.tsx`

Их функции переносим в inline-блок на `/install` (статичный список, без степпера). Удалить:
- `src/components/pwa/IOSInstallGuide.tsx`
- `src/components/pwa/AndroidInstallGuide.tsx`
- `showIOSGuide` / `showAndroidGuide` state в `Install.tsx`

### D. Auto-detect Chrome/Firefox на iPhone → честное предупреждение

Сейчас iOS-инструкция показывается даже если юзер в Chrome на iPhone (где она НЕ сработает). Добавляем детект:

```ts
const isIOSWebKit = isIOS && /safari/i.test(ua) && !/CriOS|FxiOS|EdgiOS/i.test(ua);
const isIOSChrome = isIOS && /CriOS|FxiOS|EdgiOS/i.test(ua);
```

Если `isIOSChrome` → показать **первым делом** красную плашку: «Откройте сайт в Safari — здесь установка не работает» + большая кнопка `safari-https://myuno.app/install` (на iOS открывается в Safari).

### E. Чиним «иконка не появляется» на уровне ассетов

1. **Заменить плейсхолдеры скриншотов** `public/screenshots/mobile-home.png` и `mobile-services.png` (сейчас оба 10 KB, одинаковые). Без этого Chrome не покажет богатый install UI и юзер не понимает «что я устанавливаю». Поручим юзеру загрузить 2 настоящих скриншота 1080×1920.
2. **Сделать настоящий maskable icon**. Сейчас 192/512 помечены `any maskable`, но без safe zone это даёт обрезанные иконки на Android. Добавить отдельные файлы:
   - `public/icons/icon-maskable-192.png` — иконка с safe zone (логотип в центральных 80%)
   - `public/icons/icon-maskable-512.png` — то же 512×512
   - В манифесте развести: `'any'` для оригинальных, `'maskable'` для новых.
3. **iOS apple-touch-icon без альфа-канала**. iOS не любит прозрачные apple-touch-icon — отображает чёрные углы. Перегенерировать `icon-180x180.png` с непрозрачным фоном (cream `#F7F5F1` или navy `#0A2240`).

### F. Success state — показываем КУДА ушла иконка

Сейчас экран успеха пишет «Иконка добавлена на главный экран». Добавить **скриншот / схематичный рисунок** домашнего экрана с подсветкой иконки myUNO — пользователь сразу понимает «выйди из браузера и посмотри сюда».

### G. Убрать 45-секундную задержку `MobileInstallSheet`

Сейчас drawer выскакивает через 45 секунд молчания. Это плохой UX (раздражает в момент чтения). Заменить на:
- **Триггер по событию**: после первого осмысленного действия (открыл листинг / добавил в избранное / 3-й переход по приложению).
- Не более 1 раза в 30 дней (это уже есть).

## Технические детали

### Файлы редактируем
- `src/pages/Install.tsx` — переписать как single-screen без модалок-степперов; убрать `showIOSGuide`/`showAndroidGuide` state; добавить детект iOS Chrome; добавить блок «куда смотреть после установки».
- `src/components/pwa/InstallBanner.tsx` — добавить toast «Готово!» через `sonner` после успешного `install()`.
- `src/components/pwa/MobileInstallSheet.tsx` — заменить таймер 45 сек на event-driven триггер; вытащить функцию `triggerInstallSheet()` для вызова из ключевых мест.
- `vite.config.ts` — в манифесте: разделить иконки `any` и `maskable`, дописать локализованные `name`/`description`.
- `index.html` — добавить второй `apple-touch-icon` без альфы (тот же 180×180, с фоновой заливкой).

### Файлы удаляем
- `src/components/pwa/IOSInstallGuide.tsx`
- `src/components/pwa/AndroidInstallGuide.tsx`

### Файлы создаём
- `public/icons/icon-maskable-192.png` (с safe zone) — пока через Lovable AI image gen или поручить юзеру.
- `public/icons/icon-maskable-512.png` — то же.
- `public/icons/apple-touch-180.png` — без альфы.
- `public/screenshots/mobile-home.png` — настоящий скриншот (НЕ генерим автоматом, попросим у юзера).
- `public/screenshots/mobile-services.png` — то же.

### Что НЕ трогаем
- `src/sw.ts` — service worker корректен.
- `src/contexts/PWAInstallContext.tsx` — логика `beforeinstallprompt` корректна, не меняем.
- vite-plugin-pwa конфиг (кроме манифеста) — рабочий.

## Ожидаемый результат

| Сценарий | Сейчас | Станет |
|---|---|---|
| Android Chrome, нативный prompt OK | 3 клика, 2 экрана, 45-сек задержка | **2 клика, 0 промежуточных экранов** |
| Android Chrome, prompt не сработал | 8 кликов, 3-step модалка | **3 клика, 1 экран со списком** |
| iOS Safari | 6 кликов, 3-step модалка | **2 клика, inline-инструкция** |
| iOS Chrome (failed flow) | Показывали инструкцию для Safari, юзер запутывался | **Сразу красная плашка + кнопка «Открыть в Safari»** |
| Иконка «пустая» на Android | Часто (any+maskable без safe zone) | Корректная (отдельный maskable с safe zone) |
| Иконка «чёрные углы» на iOS | Альфа-канал в apple-touch-icon | Без альфы, корректная |

После одобрения переключаюсь в default mode и реализую. Скриншоты для манифеста и финальные maskable-иконки нужно будет либо догенерить (если устраивает упрощённый вариант), либо ты пришлёшь свои файлы — спрошу в момент реализации.
