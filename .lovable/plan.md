

# Аудит и Усиление Системы Регистрации/Авторизации

## Результаты аудита

### Что работает хорошо
- 3-шаговая регистрация (Имя -> Контакты -> Пароль) в стиле Airbnb с анимациями
- Вход по email/паролю + PIN-код для быстрого входа
- Восстановление пароля: `/auth/forgot-password` -> письмо -> `/auth/reset-password` -- полная цепочка
- Реферальные коды работают при регистрации
- Уведомление админа о новых регистрациях через edge function
- Админ-панель: таблица пользователей (`ControlUsersTab`) + аналитический дашборд (`UserAnalyticsDashboard`) с графиками роста, когортами, сегментами

### Найденные проблемы

| # | Проблема | Серьезность |
|---|----------|-------------|
| 1 | Нет `autocomplete` атрибутов на полях email/password -- браузер НЕ предлагает сохранить пароль | Высокая |
| 2 | Пароль: только `min(6)`, нет индикатора сложности, нет требований к спецсимволам/цифрам | Средняя |
| 3 | Нет подтверждения пароля при регистрации (только при сбросе) | Средняя |
| 4 | Форма логина не обёрнута в `<form>` с `name` -- менеджеры паролей работают хуже | Средняя |
| 5 | Нет ссылки "Забыли пароль?" при переключении на email-логин после PIN | Низкая |

## План исправлений

### 1. Autocomplete-атрибуты для сохранения паролей браузером

Добавить стандартные `autocomplete` и `name` атрибуты на все поля ввода в `Auth.tsx`, `ForgotPassword.tsx`, `ResetPassword.tsx`:

- Форма логина: `name="login"`, email -> `autocomplete="email"`, password -> `autocomplete="current-password"`
- Форма регистрации: `name="signup"`, name -> `autocomplete="name"`, email -> `autocomplete="email"`, tel -> `autocomplete="tel"`, password -> `autocomplete="new-password"`
- Форма сброса: password -> `autocomplete="new-password"`

Это позволит Chrome, Safari, Firefox предлагать сохранить/автозаполнить учетные данные.

### 2. Индикатор сложности пароля

Создать компонент `PasswordStrengthIndicator`:
- Визуальная шкала (4 сегмента: слабый/средний/хороший/сильный)
- Проверки: длина 8+, заглавная буква, цифра, спецсимвол
- Интегрировать на шаг "Создайте пароль" при регистрации
- Zod-схема остается `min(6)` для обратной совместимости, но индикатор визуально подсказывает пользователю

### 3. Подтверждение пароля при регистрации

Добавить поле "Подтвердите пароль" на 3-й шаг регистрации (перед кнопкой "Создать аккаунт") с валидацией совпадения.

### 4. Исправление формы для менеджеров паролей

Обернуть signup-форму в тег `<form>` с `action="#"` и `method="POST"` (предотвращая submit), чтобы менеджеры паролей корректно определяли форму.
