

# Включение Coming Soon для всех внешних пользователей

## Проблема

Maintenance mode сейчас хранится **только в localStorage браузера каждого пользователя**. Дефолтное значение — `false` (сайт открыт). Это значит:

- Новый посетитель www.myuno.app → localStorage пустой → `stored === null` → дефолт `false` → видит полный сайт
- Переключатель в админке меняет состояние только **в вашем собственном браузере**

Сайт сейчас полностью открыт для всех.

## Решение

Изменить дефолтное значение maintenance mode с `false` на `true` в `MaintenanceContext.tsx`. Это означает:

- Любой новый посетитель (без localStorage) увидит страницу "Coming Soon"
- Админы с bypass-ключом в localStorage продолжат видеть полный сайт
- Когда Павел будет готов запустить сайт, он нажмёт "Launch Site" в `/admin`, и дефолт можно будет вернуть на `false`

## Технические изменения

### Файл: `src/contexts/MaintenanceContext.tsx`

**Строка 29** — изменить дефолт:

```text
// Было:
return stored === null ? false : stored === 'true';

// Станет:
return stored === null ? true : stored === 'true';
```

Также удалить неиспользуемый импорт `useLocation` (баг из аудита, строка 2).

### Важно

Это одно изменение одного символа (`false` на `true`), но оно закроет сайт для всех новых посетителей. Администраторы с bypass продолжат иметь полный доступ.

### Долгосрочная рекомендация

Для надёжного решения maintenance mode должен храниться в базе данных (например, таблица `app_settings`), а не в localStorage. Тогда переключение в админке закроет/откроет сайт для всех одновременно. Это можно реализовать как отдельную задачу.
