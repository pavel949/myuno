## Проблема

На скриншоте видно: категория **«Дом и быт» (cat-home-living)** содержит **12 сервисов в одну плоскую плитку-ряд** — Прачечная, Уборка, Сантехника, Электрика, Кондиционеры, Цветы, Сад, Дезинсекция, Замки, Хранение, Мастер, Все услуги. Это «свалка», а не каталог. Человек не понимает, что куда.

Дополнительные дыры в кластере **Жизнь**:
- **События (`event`) лежат в `Arrive → Tourism`** — для туристов. Но для резидента событие = часть повседневной жизни (вечеринки, концерты, выставки).
- **Категория «Сообщество»** пустая (только «Скоро»).
- **«Спорт»** имеет только 1 сервис — Фитнес. В БД есть пометки fitness, водные активности, но они дублируются в Arrive.
- Нет визуальной иерархии «подгруппа → сервис» — всё одной длинной кашей.

## Цель

Сделать кластер **«Жизнь»** реально полезным для повседневности: чтобы человек открыл категорию и увидел осмысленные подгруппы, а не плоский ряд из 12 иконок.

## Решение

### 1. Ввести подгруппы (sub-groups) внутри категорий

Расширяем тип `CategoryEntry` в `src/lib/catalog/taxonomy.ts`:

```ts
export interface ServiceSubGroup {
  id: string;
  labelRu: string;
  labelEn: string;
  icon: LucideIcon;
  services: ServiceEntry[];
}

export interface CategoryEntry {
  // ...existing fields
  services: ServiceEntry[];        // оставляем для обратной совместимости (FLAT_SERVICES)
  subGroups?: ServiceSubGroup[];   // НОВОЕ: опциональная группировка для UI
}
```

`FLAT_SERVICES` продолжает работать как раньше (адаптеры, тесты, поиск). UI начинает рендерить `subGroups` если они есть, иначе — плоский список.

### 2. Перегруппировать «Дом и быт» в 4 подгруппы

```text
🏠 Дом и быт (Home & Living)
├── 🧹 Уборка и быт
│   ├── Уборка       (cleaning)
│   ├── Прачечная    (laundry)
│   └── Дезинсекция  (pest-control)
├── 🔧 Ремонт и техника
│   ├── Мастер на час (handyman)
│   ├── Сантехника    (plumbing)
│   ├── Электрика     (electrical)
│   ├── Кондиционеры  (ac-repair)
│   └── Замки         (locksmith)
├── 🌿 Двор и сад
│   ├── Сад           (gardening)
│   └── Цветы         (flowers)
└── 📦 Логистика
    ├── Хранение      (storage)
    ├── Доставка воды (water-delivery — новый)
    └── Все услуги    (services hub)
```

Это совпадает с уже существующим `homeServicesTaxonomy.ts` (4 домена: maintenance / cleaning / outdoor / logistics) — мы просто впервые показываем эту структуру в UI.

### 3. Перенести Events и Досуг в «Жизнь»

- **`event`** (События): добавить копию в `Live → Family/Community` блок «Что делать вечером», оставив Events в Arrive для туристического сценария (или сделать сервис кросс-категорийным через `categoryAliases`).
- Добавить категорию **«Досуг и события» (cat-leisure)** в Live с подгруппами:
  ```text
  🎉 Досуг и события
  ├── 📅 События        (event)
  ├── 🍽️ Рестораны      (restaurant — переместить из food)
  ├── 🚀 Активности     (water — копия)
  └── 👥 Сообщество     (когда заработает)
  ```

### 4. «Еда и развлечения» → «Еда и доставка»

Переименовать `cat-food-entertainment` → `cat-food-delivery`. Подгруппы:
```text
🍽️ Еда и доставка
├── Еда вне дома: Рестораны, Маркет
└── Доставка: Доставка еды, Доставка воды, Цветы
```

### 5. «Здоровье и велнес» — добавить подгруппы

```text
❤️ Здоровье и велнес
├── 🏥 Медицина: Клиники, Аптеки, Страховка
└── 💆 Велнес и красота: Красота/SPA, Фитнес
```

(Фитнес переносим из отдельной куцей категории `cat-sports` — тогда `cat-sports` можно убрать или оставить только под спортивные школы Муай-тай / дайвинг / серфинг.)

### 6. UI: новый компонент `CategoryAccordionView`

В `src/components/catalog/` (или там где сейчас рендерится категория Discover):

- Если у категории есть `subGroups` — рендерим аккордеон/секции с подзаголовками подгрупп и плитками сервисов внутри.
- Если нет — fallback на текущий плоский grid.
- На мобильном — collapsible секции (по умолчанию первая раскрыта).
- На десктопе — все секции открыты, разделены подзаголовками.

### 7. Финальная карта Live (после реструктуризации)

```text
🏠 Жизнь (Live) — повседневность без хаоса
├── Дом и быт         (4 подгруппы, 12 сервисов)
├── Еда и доставка    (2 подгруппы, 5 сервисов)
├── Здоровье и велнес (2 подгруппы, 6 сервисов)
├── Семья и дети      (4 сервиса, без подгрупп)
├── Питомцы           (2 сервиса)
├── Досуг и события   (НОВОЕ — события, рестораны, активности, сообщество)
└── Свадьбы и события (existing — премиальный сегмент)
```

## Технические изменения

| Файл | Что меняется |
|---|---|
| `src/lib/catalog/taxonomy.ts` | + `ServiceSubGroup` тип; реструктуризация `cat-home-living`, `cat-food-entertainment`, `cat-health-wellness`; новая категория `cat-leisure`; убрать/слить `cat-sports`, `cat-community` |
| `src/components/catalog/CategoryView.tsx` (или эквивалент) | Логика рендера подгрупп — accordion на mobile, секции на desktop |
| `src/test/catalog/taxonomy-coverage.test.ts` | Обновить ожидаемое число категорий (16 → ~15-16) и добавить тест на subGroups |
| `src/lib/verticalGroups.ts`, `src/lib/nav/clusterCatalog.ts` | Адаптеры — flat-список через `FLAT_SERVICES` остаётся, но добавляем экспорт подгрупп для футера/нав |
| Migration (Supabase) | (опц.) синхронизировать `categories.slug` для удалённых/новых категорий, обновить `app_path` для events |

## Что НЕ трогаем

- 6 кластеров и `category_groups` — структура кластеров правильная.
- БД-таблицы listings/services — только метаданные категорий.
- Workspace-кластер Manage — он отдельная история.
