
# План: Оптимизация флоу бронирования недвижимости для гостей

## Анализ текущего состояния

### Текущий флоу бронирования:
1. **PropertyDetail** → Выбор дат в карточке бронирования (PropertyBookingCard)
2. **PropertyInquiry** → Повторный выбор дат + контактные данные + способ оплаты
3. Отправка запроса без оплаты

### Проблемы:
- Календарь показывается дважды (на карточке и на странице бронирования)
- Нет логики предоплаты 10%
- Нет разделения на Instant Booking (с оплатой) и обсуждение оффлайн

### Логика после оплаты:

| Способ оплаты | Действие |
|---------------|----------|
| **Онлайн (Stripe)** | Создаётся бронирование со статусом `deposit_paid`. Админ получает уведомление и блокирует даты. |
| **Оффлайн (WhatsApp)** | Открывается WhatsApp с предзаполненным сообщением со всеми деталями бронирования. Бронирование создаётся со статусом `pending_deposit`. |

## Технические изменения

### 1. Обновление PropertyInquiry.tsx
- Удалить календарь (даты приходят из URL параметров)
- Добавить блок "Предоплата 10%"
- Добавить кнопку "Обсудить оплату с myUNO"
- Интегрировать Stripe для онлайн-оплаты 10%

### 2. Создание Edge Function `create-property-deposit-checkout`
- Принимает: property_id, check_in, check_out, guests, total_amount
- Создаёт Stripe Checkout Session на 10% от суммы
- Сохраняет метаданные для последующей обработки

### 3. Обновление PropertyBookingCard.tsx
- Добавить отображение "10% предоплата" в расчёте цены
- Убедиться, что все параметры передаются в URL

### 4. Создание компонента ContactAdminButton
- Формирует сообщение с деталями бронирования
- Открывает WhatsApp/Telegram с предзаполненным текстом

### 5. Добавление статусов бронирования
- `pending_deposit` — ожидает предоплату (оффлайн)
- `deposit_paid` — предоплата получена
- Существующие статусы остаются

## Преимущества предложенного решения

1. **Упрощённый UX**: Календарь показывается только один раз
2. **Чёткая финансовая логика**: 10% невозвратная предоплата
3. **Гибкость оплаты**: Онлайн или через связь с командой
4. **Защита владельцев**: Даты блокируются только после подтверждения предоплаты
5. **Существующая инфраструктура**: Используем уже работающий Stripe (как для цветов)
